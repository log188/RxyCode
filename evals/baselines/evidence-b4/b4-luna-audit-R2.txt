## 复审结论：FAIL

仍有阻断项，不能判定 B4 通过。

### 1. 判据核对

| 判据 | 结论 | 说明 |
|---|---|---|
| 1. 前缀不可变 | **部分通过** | 消息对象未原位修改；但 `_fold_middle_section` 会把所有 `system` 消息从原位置重排到列表头部，若“前缀不可变”包含顺序/位置，则违反 CB1。且没有显式 checkpoint 参数，所有非-system 旧消息都可能被折叠。 |
| 2. 摘要模板 | 通过 | 包含 Objective / Work State / Next Move。 |
| 3. 尾部与 25% 预算 | **未充分证明** | 实现按 `tokens_after`（整个输出）比较预算，而非仅按尾部预算；可能折叠掉全部最近消息。新增测试断言实际失效：`max(..., tokens_before)` 几乎总是 `tokens_before`，并未真正约束 25%。 |
| 4. 遥测 | **失败** | `_estimate_chars()` 返回字符数，但遥测字段命名为 `tokens_before/after`，note 却声明“char/3 estimates”。代码没有执行 `/3`，因此遥测数值与声明不一致。 |
| 5. assistant↔tool 成对 | **部分通过** | 常规连续配对可保留；但发现未完整配对时，代码仍会把 assistant 放入折叠段，最终依赖 `tool_pair_integrity` 回退。这不符合“显式保持成对、不依赖失败回退”的修复要求。 |
| 6. threshold/reserved | 通过 | `usable = threshold - reserved` 后再判断是否压缩，逻辑方向正确。 |

### 2. CB1-CB8

至少以下硬约束仍未满足：

- **CB1：前缀不可变**  
  没有明确断点/缓存前缀边界；同时 system 消息会被重排。
- **CB4：压缩不得破坏历史结构**  
  配对处理不完整，异常配对路径仍依赖最终回退。
- **遥测约束**  
  `tokens_*` 的单位实现与声明不一致，无法作为可靠命中率比较依据。

### 3. 必须修复

1. 明确 checkpoint/prefix 边界，禁止将断点前的非-system 消息折叠。
2. 修正 `_estimate_chars` 与遥测命名：要么真正返回 `len/3`，要么统一称为 `chars_*`。
3. 重写配对边界处理：assistant 与其所有 tool result 必须整体移动到折叠段或尾部，不得先生成孤儿结构再依赖回退。
4. 修正 25% 测试断言，移除 `max(..., tokens_before)` 这一使断言失效的逻辑。

因此本轮仍为 **FAIL**。
