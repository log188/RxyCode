def _make_stats():
    from RxyCode.RxyCode1_1_0.utils.streaming import TokenStats

class TestHitRateMetricsFields:
    """B1 判据：度量字段存在性 + 公式口径。"""

    def test_metric_fields_exist(self):
        stats = _make_stats()
        assert hasattr(stats, "prompt_tokens")

        assert hasattr(stats, "cache_hit_rate")

    def test_cache_hit_rate_formula(self):
        stats = _make_stats()
        stats.add_real_usage(3000, 0, 2000)
        assert stats.cache_hit_rate == pytest.approx(2000 / 3000 * 100)

    def test_cache_hit_rate_zero_division_protected(self):
        stats = _make_stats()
        assert stats.cache_hit_rate == 0.0

    def test_cache_hit_rate_accumulates_correctly(self):

        stats.add_real_usage(1000, 0, 500)
        stats.add_real_usage(1000, 0, 0)

class TestHitRateTotalsVsLatest:
    """B1 实现参考（Pi 双口径）：totals 累计 vs latest 最近一次 assistant 请求。"""

    def test_latest_request_tracked(self):
        stats = _make_stats()
        stats.add_real_usage(1000, 100, 800)
        latest = stats.latest_request
        assert latest["prompt_tokens"] == 1000
        assert latest["hit_tokens"] == 800
        assert latest["hit_rate"] == pytest.approx(80.0)

    def test_latest_overwritten_by_next_request(self):
        stats = _make_stats()
        stats.add_real_usage(1000, 100, 800)
        stats.add_real_usage(2000, 200, 0)
        latest = stats.latest_request
        assert latest["prompt_tokens"] == 2000
        assert latest["hit_tokens"] == 0
        assert latest["hit_rate"] == 0.0

    def test_latest_untouched_before_first_request(self):
        stats = _make_stats()
        assert stats.latest_request["prompt_tokens"] == 0
        assert stats.latest_request["hit_tokens"] == 0
        assert stats.latest_request["hit_rate"] == 0.0

    def test_totals_remain_cumulative_while_latest_is_single(self):
        stats = _make_stats()
        stats.add_real_usage(1000, 0, 800)
        stats.add_real_usage(1000, 0, 200)
        assert stats.prompt_tokens == 2000
        assert stats.cache_hit_tokens == 1000
        assert stats.latest_request["prompt_tokens"] == 1000
        assert stats.latest_request["hit_tokens"] == 200

    def test_reset_clears_latest(self):
        stats = _make_stats()
        stats.add_real_usage(1000, 0, 800)
        stats.reset()
        assert stats.latest_request["prompt_tokens"] == 0
        assert stats.latest_request["hit_tokens"] == 0

grep 代码库时必须逐条对照以下模式：任何一条命中都会让缓存"静默失效"——无报错、命中率悄悄归零（Anthropic 官方文档 + Claude Code 实践）。这些内容一律移到断点之后/前缀之外：

1. system prompt 里插入 `datetime.now()`/时间戳；
2. `uuid4()`/随机 id 进前缀；
3. `json.dumps` 不排序（遍历 set、dict 顺序不稳定 → 同一内容的序列化字节抖动）；
4. 按用户/会话 id 插值进 system；
5. 条件拼接 system 段（配置开关变化改变字节）；
6. 工具 schema 顺序/字段顺序变动；
7. 日期在 system 中（Claude Code CHANGELOG："Improved prompt cache hit rates by moving date out of system prompt"）；
8. 换模型/换 effort 档位（Claude：缓存键 = 模型 + effort + fast-mode 头）。

**检测手段**：对 system+tools 规范化（确定性排序）后做 SHA-256，跨轮对比（Reasonix `CaptureShape`：SystemHash/ToolsHash/PrefixHash + CompareShape 输出 PrefixChanged 归因）：

```python
import hashlib
import json


def prefix_digest(system: str, tools: list) -> str:
    """对 system+tools 做确定性序列化后取 SHA-256；跨轮对比即可发现静默失效源。"""
    norm = json.dumps(
        {"system": system, "tools": sorted(tools, key=lambda t: t["name"])},
        sort_keys=True, ensure_ascii=False, separators=(",", ":"),
    )
    return hashlib.sha256(norm.encode("utf-8")).hexdigest()


# 跨轮断言：任何一轮的 digest 与上一轮不同，即前缀被某处改写（归因到 §0.4 CB1）
assert prefix_digest(system, tools) == prefix_digest(system_turn2, tools_turn2)
```

本清单同时写进 `tests/test_cache/test_stable_prefix.py`（对 B2 的模板与工具列表做快照对比），并作为 §4.5"静默失效源禁止清单"的出处。

### 压缩后缓存不降：十原则落地

本小节把压缩的 10 条原则逐条落成本卡实现要点（调研报告 §4 与 Reasonix/Claude/Codex/Pi/Qwen 源码级结论），并先给出**现有实现差距对照**：

| 现状（`core/agent_v2.py` 当前快照） | 违背的原则 | 要改成什么 |
|---|---|---|
| 70% 固定阈值触发（`budget = int(self._context_window() * 0.7)`，`:2461`） | 原则 4（分级触发） | 分级触发：snip(0.6) → prune(0.8) → summary(0.9 强制)；输出预留（reserved）计入可用空间；阈值读 `ModelCapabilities.compaction_threshold`（Phase A） |
| `ContextCompressor._middle_truncate` 原位改写已发送 ToolMessage（`m.content = new_content`，`:2475-2477`） | 原则 1、5（压缩=唯一 cache-reset point；切割纪律） | 只折叠断点之后的 assistant/tool 中间段；tool_calls↔tool result 配对守恒；永不改写已发送消息 |
| 无摘要重建（只有截断，没有"摘要置末+尾窗"布局） | 原则 6（确定性重建） | 摘要置末 + 保留最近 N token 原始消息（Codex 20k 本地/64k 远程）+ retainedTail 式 checkpoint |
| 无遥测（压缩事件不记录 tokens_before/after、命中率不对比） | 原则 8（遥测） | tokens_before/after + cache_read 对比 + 会话级聚合命中率 Σhit/(Σhit+Σmiss) 不随压缩清零 |

**十原则与实现要点**

1. **压缩=唯一的 cache-reset point**：平时严格 append-only；前缀只能在压缩那一刻变（Reasonix SPEC §3.6："This is the only point where the prompt prefix changes"）。实现要点：压缩入口唯一化——工具循环、research、会话恢复全部只能走 `core/compaction.py` 一个入口；压缩之外任何"改写历史"的调用都是 bug。
2. **摘要请求=旧完整前缀+追加摘要指令**：压缩时把摘要提示词追加在现有完整会话后发送（历史打 cache read，只对摘要指令付 write；Claude CHANGELOG"压缩请求保留图片以复用 prompt cache"；Codex `compact.rs` 同款）。实现要点：摘要请求复用原会话前缀，禁止从零拼"只含摘要材料"的新前缀。
3. **摘要请求隔离**：一次性摘要请求用全新 routing session ID + 禁用 prompt-cache 写入（Pi `cacheRetention:"none"` + uuidv7："one-off prompts are unlikely to be reused"）。实现要点：摘要请求的 `prompt_cache_key` 置空/独立命名空间，避免污染会话主键。
4. **分级触发，免费手段先行**：snip（0.6，确定性头尾保留标记）→ prune（0.8，短占位符）→ summary（0.9 强制）；prune 省出空间够就跳过摘要调用（经济门槛：可折叠区 ≥400 tokens 才值得调摘要器）；0.5 以下只发 notice 不改前缀（Reasonix）。实现要点：删掉 70% 固定值，触发阈值读 Phase A 能力元数据。
5. **切割纪律**：tool_calls 与 tool result 配对守恒（永不单独删）；折叠边界向后对齐（尾窗不以孤儿 tool 消息开头）；**用户轮逐字保留**；**已生成 digest 逐字保留（永不二次摘要）**；thinking/reasoning 块不可改写（MiMo/MiniMax 400 硬约束；Qwen `/compress-fast` 只剥旧 thinking）；只折叠 assistant/tool 中间段；错误输出（`error:`/`blocked:`）保留。实现要点：压缩器输入="断点后消息段"，输出=配对守恒校验通过的折叠结果，压缩后断言无孤儿 tool_call（API 400 防线）。
6. **压缩后新前缀确定性重建**：摘要置末 + 保留最近 N token 原始消息（Codex 20k 本地/64k 远程；Reasonix 尾窗 16384 预算；Pi keepRecentTokens 20000）+ retainedTail 式 checkpoint（压缩条目内嵌保留上下文快照，重建从 checkpoint 开始=字节级确定，reload/resume 后仍可命中）。实现要点：同一历史两次压缩必须产生相同前缀（测试断言字节级相同）。
7. **压缩前落盘、压缩后回填**：flush 记忆（Grok `soft_threshold_tokens=4000` 提前量）→ 压缩 → 压缩后记忆检索回填被丢关键上下文（GLM"记忆文件压缩后从磁盘重载"；MiMo checkpoint 重建 = 最新 checkpoint + MEMORY.md + task progress + 保留最近消息 + 按 token 预算重要性排序注入）。实现要点：压缩触发前调用 `memory/manager.py` flush；压缩后按重要性排序回填。
8. **遥测**：tokens_before/after + cache_read 对比 + **会话级聚合命中率 Σhit/(Σhit+Σmiss) 不随压缩清零**（Reasonix `event.go` 注释原文："which doesn't crater on a short turn or after compaction"；Grok OTEL `grok_code.compaction{duration_ms, tokens_before, tokens_after}`）。实现要点：压缩事件写审计（开始/结束/边界/命中率前后对比，§7.2）；聚合口径是会话累计，不是单轮窗口。
9. **TTL 感知冷恢复门控**：热（TTL 内）=逐字重放吃命中；冷（超 TTL）=先压缩（prune/折叠出 digest+尾窗）再发，省整段重放成本（Reasonix 24h 档，测试三例：`TestColdResumePrunesAndPersists` / `TestWarmResumeLeavesHistoryAlone`）。实现要点：恢复路径读 B9 契约的 `cache_ttl_hours` 判断冷/热。
10. **卡住保护**：连续两轮压缩仍触发线上→暂停自动压缩（compactStuck 闩锁）；压缩后落在 [0.5,0.8) 区间清零闩锁防误判。实现要点：`core/compaction.py` 内做闩锁状态机，与 B7 的 stuck detector 独立不互扰。

### 实现参考（Pi 源码实证）

Pi 是 B4 设计蓝本（`docs/superpowers/sdd/agent-research/pi-source-dive.md` §1-5、§11），参数与边界如下：

- **触发与阈值**：`contextTokens > contextWindow - reserveTokens`，**reserveTokens=16384、keepRecentTokens=20000**（compaction.ts:132-136, 235-238）；用真实 usage（含 cacheRead）判阈值——纯内容估算忽略 cacheRead 会误判（overflow.ts:146）
- **切割纪律**：toolResult 禁切（必须跟随其 toolCall）；切在 assistant（带 toolCall）时其 tool results 在保留段；split-turn 的 turn 前缀单独摘要（预算 0.5×reserve）
- **摘要请求隔离**：`cacheRetention:"none" + sessionId:uuidv7()`（compaction.ts:562-581）——不挂 cache_control/prompt_cache_key、无 session-affinity 头，既不读也不写主对话缓存命名空间（测试断言 compaction.test.ts:574）
- **摘要预算与格式**：输出预算 **0.8×reserve**；序列化 tool result 截断 **2000 字符** + `[...N more truncated]`；迭代更新用 UPDATE prompt 显式"PRESERVE all existing information"（防二次摘要漂移）
- **防重触发**：压缩后第一条消息 timestamp ≤ 压缩时间戳则跳过（agent-session.ts:1981-1986）；overflow 只允许一次 compact-and-retry

- [ ] 后台 fork 摘要不阻塞主循环（测试）；
- [ ] 流式与断点策略一致性测试通过；
- [ ] TTFT 命中/未命中对比记录存在（真实数字）；
- [ ] evals 基线无回归；
- [ ] B1–B10 全部卡都有独立 commit 和真实验收输出。

**常见坑**

- **写操作并行副作用**：两个并行写同一文件 = 返工 + 冲突；并发只对读/搜索类安全；
- **并发下消息顺序抖动**：并行工具结果按完成顺序落消息 = 前缀每轮形态不同 = 击穿缓存；结果必须按确定性顺序落盘（与 B2 的排序纪律同源）；
- **TTFT 采样口径不一致**：命中/未命中对比必须同前缀、同模型、同后端，否则对比无意义；
- **后台摘要污染前缀**：fork 的摘要任务如果改写已发送消息，等于 G2 换个马甲。

4. **示例代码**（契约读取唯一入口 + usage 归一化，可运行）：

```python
"""model_catalog.json cache_contract 读取与 usage 归一化（B9 规格，可运行）。

契约读取唯一入口：B2 断点分派 / B3 TTL / B4 压缩决策 / B6 token 治理一律经此，
禁止散落 if-elif 判断各家模型。
"""
import json
from pathlib import Path
from typing import Optional

CATALOG_PATH = Path("config/model_catalog.json")
_catalog: Optional[dict] = None


def load_catalog() -> dict:
    global _catalog
    if _catalog is None:
        _catalog = json.loads(CATALOG_PATH.read_text(encoding="utf-8"))
    return _catalog


def get_contract(model_id: str) -> dict:
    """返回 cache_contract；未识别模型抛 KeyError（CB8 由调用方兜底为现状行为）。"""
    return load_catalog()["models"][model_id]["cache_contract"]


def read_cached_tokens(model_id: str, usage: dict) -> int:
    """按 usage_fields.cached 的 JSON 路径读取命中数（各家字段差异在此归一化）。"""
    contract = get_contract(model_id)
    node: dict = usage
    for part in contract["usage_fields"]["cached"].split("."):
        node = node.get(part, {})
    return node if isinstance(node, int) else 0


def hit_discount(model_id: str) -> float:
    """命中价/未命中价（DeepSeek flash=0.02），供成本核算与模型路由比较。"""
    return get_contract(model_id)["cache_hit_discount"]
```

```python
"""core/bridge/ 示例：单 agent 桥接层（B10 规格，可运行骨架）。

复用 appserver/agent_worker.py 的 killable 子进程模式与 appserver/jsonrpc.py 的
NDJSON JSON-RPC 封装；每个桥接 agent 独立 session、lineage-only，不复制主历史。
"""
import asyncio
import json
from abc import ABC, abstractmethod
from dataclasses import dataclass
from typing import AsyncIterator, Optional

STDIN = asyncio.subprocess.PIPE
STDOUT = asyncio.subprocess.PIPE


@dataclass
class BridgeConfig:
    """成本控制：token 预算 + 时间预算 + 结果截断，全部可配。"""
    token_budget: int = 50_000        # 超出即 kill
    time_budget_s: float = 300.0      # 超时 kill（asyncio.timeout 兜底）
    max_result_chars: int = 2000      # 回流主 harness 的摘要上限（1-2K token）


class AgentBridge(ABC):
    """单 agent 桥接抽象基类：spawn → 任务注入 → 流式事件 → kill。"""

    def __init__(self, cfg: BridgeConfig) -> None:
        self.cfg = cfg

    @abstractmethod
    async def start(self) -> None:
        """spawn 子进程并完成 ACP/CLI 握手。"""

    @abstractmethod
    def invoke(self, task: str) -> AsyncIterator[dict]:
        """流式产出 agent_message_chunk/agent_thought_chunk/tool_call/plan/result。"""

    @abstractmethod
    async def stop(self) -> None:
        """超时/预算超限时 kill 并回收审计输出。"""

    @abstractmethod
    def usage(self) -> dict:
        """本桥接的 usage；各家字段按 B9 契约归一化。"""


class ClaudeCodeBridge(AgentBridge):
    """ACP（JSON-RPC over stdio）适配器：spawn `claude`，NDJSON 封装。"""

    def __init__(self, cfg: BridgeConfig, cmd: Optional[list] = None) -> None:
        super().__init__(cfg)
        self._cmd = cmd or ["claude", "--acp"]
        self._proc: Optional[asyncio.subprocess.Process] = None

    async def start(self) -> None:
        self._proc = await asyncio.create_subprocess_exec(
            *self._cmd, stdin=STDIN, stdout=STDOUT)

    async def invoke(self, task: str) -> AsyncIterator[dict]:
        req = {"jsonrpc": "2.0", "method": "session/new_prompt",
               "params": {"text": task}, "id": 1}
        self._proc.stdin.write((json.dumps(req) + "\n").encode())
        await self._proc.stdin.drain()
        async for line in self._proc.stdout:      # NDJSON 逐行（appserver/jsonrpc.py 同款）
            msg = json.loads(line)
            method = msg.get("method")
            if method in ("agent_message_chunk", "agent_thought_chunk", "tool_call"):
                yield {"type": method, "content": msg.get("params", {})}
            elif method == "session/result":
                yield {"type": "result", "content": msg["params"]["result"]}
                return

    async def stop(self) -> None:
        if self._proc and self._proc.returncode is None:
            self._proc.kill()                     # killable 子进程（agent_worker.py 语义）
            await self._proc.wait()

    def usage(self) -> dict:
        return {}                                  # 按 B9 usage_fields 解析后回填


class GrokBuildBridge(AgentBridge):
    """CLI 透传兜底：spawn `grok agent stdio`，解析事件流。"""

    async def start(self) -> None:
        self._proc = await asyncio.create_subprocess_exec(
            "grok", "agent", "stdio", stdin=STDIN, stdout=STDOUT)

    async def invoke(self, task: str) -> AsyncIterator[dict]:
        req = {"type": "task_delegate", "target": task,
               "lineage": ["main-session-ref"]}   # lineage-only，不复制主历史
        self._proc.stdin.write((json.dumps(req) + "\n").encode())
        await self._proc.stdin.drain()
        async for line in self._proc.stdout:
            yield json.loads(line)

    async def stop(self) -> None:
        if self._proc and self._proc.returncode is None:
            self._proc.kill()
            await self._proc.wait()

    def usage(self) -> dict:
        return {}


async def run_official_agent(bridge: AgentBridge, task: str) -> str:
    """工具注册：run_official_agent（白名单默认禁用）。"""
    await bridge.start()
    chunks: list[str] = []
    try:
        async with asyncio.timeout(bridge.cfg.time_budget_s):   # 超时 kill
            async for ev in bridge.invoke(task):
                if ev.get("type") == "result":
                    chunks.append(ev["content"])
    except TimeoutError:
        return "[bridge] time budget exceeded; process killed"
    finally:
        await bridge.stop()
    return "\n".join(chunks)[: bridge.cfg.max_result_chars]     # 结果截断回流


async def main() -> None:
    cfg = BridgeConfig(token_budget=30_000, time_budget_s=180.0)
    bridge = GrokBuildBridge(cfg)
    summary = await run_official_agent(bridge, "scan repo for TODO comments")
    print(f"回传摘要（1-2K token 内）：{summary[:200]}…")


if __name__ == "__main__":
    asyncio.run(main())
```

**缓存纪律**（桥接不破坏主链路）

- 独立子进程/独立 session/独立前缀；
- **lineage-only 不复制主历史**（只带任务描述+引用）；
- 结果摘要 1-2K token 回流主 harness；
- 主链路前缀零污染（验收：`/status` cache_rate 对比不变）。

**成本控制**

- token 预算 + 时间预算 + 超时 kill + 结果截断，全部可配；进程可池化复用。

**验收标准**

- 功能：委托跑通、流式事件、结果回收、超时 kill 各一条命令（pytest + 手工 `/bridge`）；
- 缓存：桥接任务前后 `/status` cache_rate 不降（主链路零污染）；
- 成本：预算上限生效（token/时间超限即 kill，测试断言 + 审计记录）。

**模型限制性规范**（per-agent 契约，继承 B9）

1. 每个桥接 agent 按所选模型读 B9 `cache_contract`，不写散落判断；
2. thinking 参数按 `thinking_param` 注入（MiMo `{"type":"enabled"}` 等）；thinking 开启时 temperature/top_p 不得传自定义值（MiMo 强制 1.0/0.95，传了无效）；
3. reasoning_content 回传：assistant 历史完整回传（MiMo/MiniMax 缺失=400；DeepSeek 工具循环必回传）；原生 `<think>` 块不得删改；
4. 窗口：max_completion_tokens 按模型契约预留（MiMo 覆盖思考+答案；Grok 只约束主内容）；
5. 缓存参数：`prompt_cache_key` 会话期恒定（Kimi 必填）；无 cache_control 的模型（DeepSeek/Grok/MiMo 系）绝不注入；
6. usage 字段：按 `usage_fields` 归一化（Kimi 流式需 include_usage）；
7. 禁止事项：桥接 agent 不得改写主 harness 前缀；lineage-only；结果摘要 ≤1-2K token；超预算/超时一律 kill 不留僵尸进程。

**必须实现**

- `AgentBridge` 基类 + ACP 适配器 + CLI 兜底适配器；
- `run_official_agent` 工具注册（白名单默认禁用）+ `/bridge` 命令；
- 超时/预算 kill + 结果截断；
- 主链路前缀零污染测试。

**建议文件**：`core/bridge/base.py`、`core/bridge/acp.py`、`core/bridge/cli.py`、`core/bridge/lifecycle.py`、`appserver/agent_worker.py`（复用）、`appserver/jsonrpc.py`（复用）、`tests/test_bridge/test_agent_bridge.py`。

**常见坑**

- **桥接改写主链路**：桥接是旁路子进程，任何"把桥接历史并进主消息"的做法都是前缀污染；
- **僵尸进程**：超时后必须 kill+wait，靠 `asyncio.timeout` 抛异常不等于进程已回收；
- **lineage 泄漏**：把整个主历史传给桥接 agent = token 翻倍 + 前缀污染双输；
- **摘要回流超限**：回流摘要超过 1-2K token 会撑大主前缀，截断是硬边界不是建议。

## §6 安全、成本和失败处理

### 6.1 缓存边界

```text
系统前缀（system+tools+历史）
  ↓ 前缀逐字节不变（CB1）；敏感动态内容一律消息化（CB7）
Provider 缓存
  ↓ 断点预算（CB2）；失败结果不缓存（CB6）
应用层缓存（precise_cache / semantic_cache）——本 Phase 不碰
```

任何绕过其中一层的"方便 API"（比如在工具里直接拼 system）都不允许进入生产路径。敏感信息（secret/token/authorization）不得进入会被持久化的前缀与预热请求（沿用 Phase A 的脱敏纪律）。

### 6.2 成本默认保守

- 断点 TTL 默认 5m 档（1h 档写入价更高，按配置启用，不默认开）；
- 预热/保活默认关闭；开启时有预算保护（保活空请求本身有写入价）；
- reviewer 重试默认关闭，只对重要任务开启；
- 压缩 LLM 摘要路径默认关闭（确定性折叠是默认），开启时输入要有预算；
- 每张卡的 token 消耗对比如实记录，不隐藏压缩带来的成本。

### 6.3 失败分类

| 类别 | 示例 | 是否重试 |
|---|---|---|
| `cache_miss` | TTL 过期、前缀被破坏、配置重建 | 不重试；按 B4/B5 度量并解释 |
| `cache_invalid` | provider 拒绝 cache_control 字段（DeepSeek 版本差异） | 按 provider 能力降级（不注入），记录警告 |
| `provider_error` | API 暂时错误 | 按 Provider policy 小次数重试（沿用 Phase A） |
| `context_overflow` | 压缩触发仍爆窗 | 强制确定性折叠 + 输出预留（B4） |
| `stuck_loop` | 死循环检测触发 | 截断回环起点 + 重发最后用户指令（B7） |
| `invalid_result` | 结构化输出解析失败 | 错误回喂一次（B7），不无限重试 |
| `internal_error` | runtime bug | 终止并保留审计证据，不吞异常 |

## §9 与后续 Phase 的接口

> 后续 Phase 全部顺延一个字母：Phase C（单 Agent 内核异步化，新增）、Phase D（隔离式子代理，原 B）、Phase E（多 Agent 运行时与共享事件总线，新增）、Phase F（专家团编排，原 C）、Phase G（Desktop 工作台×3，原 D）、Phase H（多模型协作，原 E）、Phase I（多模态，原 F）、Phase J（人格接口，原 G）。本 Phase 的缓存契约是它们的公共前置。

### 9.1 Phase D：隔离式子代理（原 B）

Phase D 的每个 Child Session 独立会话、独立上下文——**每个 Child 都要遵守本 Phase 的前缀纪律与断点预算**。Child 的消息组装器不得复制一套缓存逻辑；断点预算、压缩器、度量管道必须复用本 Phase 的 `core/cache_policy.py` 与 `core/compaction.py`（对应原 B 文档"不得再写一套 runtime"的同一原则）。

### 9.2 Phase F：专家团编排（原 C）

Coordinator 的汇总消息、Blackboard 内容、角色路由指令都是**动态内容**，必须消息化追加到断点之后（CB7），不得拼进任一专家的 system 前缀。专家团的每个 Agent 独立前缀 → 独立命中率，度量和审计按 session 维度切分。

### 9.3 Phase G：Desktop 工作台×3（原 D）

Desktop 消费本 Phase 的度量数据：状态栏 `cache_rate`、provider_cache 三字段、压缩事件与命中率前后对比、TTFT 对比。Renderer 只展示数据，不自己计算命中率，不触碰缓存前缀逻辑。

### 9.4 Phase H：多模型协作（原 E）

**切模型 = 缓存失效清单第一条**（调研报告 §2.5 失效清单）。Phase H 的角色级模型切换必须触发前缀重建与命中率基线切换；每角色独立 `prompt_cache_key` 命名空间，不能共享 session_id。

### 9.5 Phase I：多模态（原 F）

附件/图像 ContentBlock 按内容寻址进消息（不内联进 system）；附件变更不得改写已有前缀。视觉内容的 token 估算（`count_image_tokens`）与压缩预留（B4 的 reserved）必须联动，防止多模态请求爆窗。

### 9.6 Phase J：人格接口（原 G）

Persona 是最高危的动态 system 来源：人格内容、经验蒸馏、业务视图**只能作为消息/块追加到断点之后**，绝不能改写 system 模板（CB1/CB7）。Persona 激活/切换动作必须记录为缓存失效事件。

### 9.7 LinkAgent

LinkAgent 通过公开协议消费本 Phase 的度量（`/status` 的 `cache_rate`、`provider_cache` 三字段与基线文件引用），不得 import `core/cache_policy.py` 的私有实现。

## §10 Phase B 完成定义

Phase B 只有在以下条件全部满足时才算完成：

1. 命中率从 <90% 基线提升到 ≥99% 区间，且有 `evals/baselines/cache-hit-rate.json` 全程证据链；
2. system 前缀逐字节稳定（B2 纪律），动态内容全部消息化；
3. 断点预算（≤4、tools→system→messages、TTL 5m/1h）按 provider 能力分派（B3）；
4. 压缩不毁前缀、不拆 tool 对、system 不裁剪（B4），压缩后命中率有度量证据；
5. 会话复用 append-only、预热/保活默认关闭且有签名校验（B5）；
6. token 治理生效（截断/按模型上限/去重/few-shot 分派，B6）；
7. 不返工机制兜底（错误回喂/死循环/快照/reviewer 门，B7）；
8. 并行与延迟有 TTFT 证据（B8）；
9. evals 19 任务基线无回归；单 Agent 默认路径零回归（CB8）；
10. Composer 2.5 主写并完成最终合并，Grok 只做 provider 缓存资料核查，Sonnet 只做可选预审。

**下一步只能是 Phase C（单 Agent 内核异步化，新增）、Phase D（隔离式子代理，原 B）**。Phase D 的每个 Child 会话继承本 Phase 的稳定前缀、断点预算与度量管道，不能再次发明缓存逻辑。
