### 3. `_execute_tools_parallel` 并发安全

存在以下问题：

1. `results_by_id` 以 `call_id` 为键；若 ID 为空、重复，结果会覆盖，破坏 `tool_pair_integrity`。
2. 读写混合调用时，读工具全部先并发执行，写工具随后才串行执行，不能保证原始调用顺序。
3. 写工具与读工具 ID 发生冲突时，写工具可能错误复用读工具结果。
4. `gather(return_exceptions=True)` 的异常处理本身合理，Semaphore 限制也正确。

### 4. TTFT 打点

当前代码：

```python
_stream_start = time.monotonic()
...
if _first_chunk and token_stats.ttft_ms is None:
    token_stats.record_ttft(...)
```

问题：

- 起点包含 client 初始化、缓存控制处理和消息转换，不是严格的“请求发出时间”。
- 任意首个 provider chunk 都会打点，未确认包含内容。
- 依赖 `token_stats.ttft_ms is None`，生产请求之间若未显式 `reset_ttft()`，后续请求可能不记录 TTFT。应在每次请求开始时重置，或使用请求级局部统计。

## 阻断项及修复建议

1. 将后台压缩移出事件循环：使用 `asyncio.to_thread()` 或独立进程。
2. 并行结果不要仅以 `call_id` 建索引，改用原始位置索引；同时校验重复/空 ID。
3. 明确读写混合调用的执行顺序，至少保证写操作与原始调用顺序一致。
4. 修正 TTFT 起点和首内容 chunk 判定，并保证每次请求独立记录。
5. 增加失败不缓存、动态内容不进入前缀、断点预算和压缩前缀稳定性的行为测试。
6. 提供 B8 独立 commit hash，以及 B1–B10 独立 commit 和真实验收输出。

因此本轮不能验收通过。
