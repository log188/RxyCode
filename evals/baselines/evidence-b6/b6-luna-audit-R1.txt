## 阻断项

### 1. JSON 截断不保证满足字符上限

`_truncate_json_chars()` 对以下情况可能返回超过 `char_limit` 的合法 JSON：

- 顶层是超长 JSON 字符串；
- 顶层是超长整数；
- 只有一个字段且字段名本身很长；
- 容器无法继续裁剪时直接 `return rendered`。

例如：

```python
json.dumps("x" * 5000)
```

进入 `_truncate_json_chars()` 后，字符串没有被处理，最终仍可能远超 2000 字符。

应修复为：无论 JSON 类型如何，最终结果都必须满足上限；必要时将值替换为 `null`、空容器或裁剪字符串，并增加上述边界测试。

### 2. 小于截断标记长度时，普通文本也可能超限

```python
marker = "\n...[truncated]...\n"
budget = max(1, char_limit - len(marker))
```

当 `char_limit < len(marker)` 时，返回结果必然大于 `char_limit`。应针对极小配置值增加处理逻辑。

### 3. 去重使用“截断后的内容”计算指纹，可能误伤

当前调用顺序为：

```python
truncated = self._truncate_tool_text(...)
self._dedupe_tool_output(tool_name, truncated)
```

两个原始工具结果只要差异位于被截掉的区域，截断后即可得到相同指纹，第二条会被错误替换为 duplicate placeholder。

应对**原始工具输出**计算结构化指纹，再对消息内容进行截断；或者在指纹中保留截断状态及内容摘要。

### 4. CB8 默认行为发生改变

新增默认配置：

```python
"tool_output_max_chars": 2000
```

这会使未显式开启 B6 开关的现有行为从“不截断”变成默认截断，违反：

> 默认值不变；未开启配置开关时行为与现状一致。

建议：

- 默认值设为 `0` / `None`；
- 增加独立的 B6 开关；
- 只有显式启用时才执行字符截断。

当前通过 monkeypatch 关闭 B6 以适配旧测试，反而证明默认行为已经改变。
