## 阻断问题

### 1. `_synthesis_with_tools` 会触发 `NameError`

函数只导入了：

```python
from langchain_core.messages import AIMessage
```

但随后使用：

```python
ToolMessage(...)
```

未导入 `ToolMessage`。因此“合成轮 DSML 兜底”路径实际会失败。

**修复：**

```python
from langchain_core.messages import AIMessage, ToolMessage
```

### 2. stuck 检测没有真正截断外层工具轮

当前 `break` 位于：

```python
for tc in tool_calls:
    ...
    if stuck:
        ...
        break
```

该 `break` 只跳出当前工具调用循环，外层：

```python
for round_num in range(max_rounds):
```

仍会继续执行下一轮，并可能再次调用 LLM。

**修复建议：**

增加 `stuck_triggered` 标志，在内层循环结束后跳出外层循环，或直接使用明确的外层控制流：

```python
stuck_triggered = False
...
if stuck:
    stuck_triggered = True
    break

if stuck_triggered:
    break
```

并补充集成测试，验证触发后不会产生下一次 LLM 调用。

### 3. Git 快照未覆盖合成轮 LLM 调用

`_synthesis_with_tools()` 内再次调用 `_raw_stream(messages)`，但调用前没有 `_capture_git_snapshot()`。若验收标准解释为“每次 LLM 调用前捕获”，此处不满足。

## DSML 解析专项

- 无 DSML 返回 `None`：通过。
- 标准 `<dsml>`、直接 `<tool_calls>`、`||DSML||`、全角竖线变体：测试覆盖充分。
- XML 转义参数：通过。
- 但解析依赖完整 XML；若 DSML 前后包含普通说明文本，`ET.fromstring("<root>...</root>")` 可能失败。
- 工具调用文本在解析前已被流式发送，可能泄漏 DSML 协议文本。

## PowerShell 转换专项

新增测试覆盖项均通过。未发现明显破坏既有测试的证据；但全局正则替换 `pwd`、`2>/dev/null` 可能误改引号中的普通文本，建议后续增加带引号参数的回归测试。
