结论：**FAIL**

R2 的基本回归场景已覆盖，但引号保护仍未闭合，不能通过复审。

阻断项：

1. **未闭合引号仍会被转换**
   `_protect_quoted` 对未闭合引号仅保留引号本身，不建立保护范围。例如：

   ```text
   echo "2>/dev/null
   ```

   会被转换为：

   ```text
   echo "2>$null
   ```

   与“引号内文本不改写”的安全目标不一致。应至少将未闭合引号后的剩余文本视为受保护内容，或明确拒绝转换。

2. **转义引号会错误截断保护范围**
   使用 `find()` 查找下一个同类引号，未处理：

   ```text
   echo "a \" 2>/dev/null"
   echo "a `" 2>/dev/null"
   ```

   （分别对应 POSIX/PowerShell 常见转义）。后续文本可能被误认为引号外内容并改写。`grep/find` 的提前解析也存在同样问题。

3. **占位符存在碰撞和恢复污染风险**
   固定形式 `\x00Q{idx}\x00` 未验证输入中是否已有相同文本，且 `_restore_quoted` 使用多次全局 `replace`。例如某个引号内容中包含另一个占位符，恢复顺序可能二次替换并改变原文。

   应使用保证不出现在原命令中的随机哨兵，并采用单次扫描/正则回调恢复。

4. **新增 grep/find 解析可能丢失参数**
   `grep` 仅捕获一个 `\S+` 文件参数：

   ```text
   grep -n "pat" file1 file2
   ```

   会丢失 `file2`。同时未处理带引号路径、转义引号及复杂参数组合。需补充参数保留测试并修正解析。

5. **`||` 之后的 `pwd` 不会转换**
   `pwd` 转换发生在 `||` 转换之前：

   ```text
   echo x || pwd
   ```

   可能得到：

   ```powershell
   echo x; if (-not $?) { pwd }
   ```

   应在控制流重写后再次处理，或统一采用结构化解析。
