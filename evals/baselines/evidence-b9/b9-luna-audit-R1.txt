### 阻断项

1. **Qwen 显式断点契约实际不会生效**

   `_apply_cache_control` 在新增契约判断前已有：

   ```python
   if caps_provider != "anthropic":
       return messages
   ```

   因此 Qwen 虽然配置为：

   ```json
   "cache_mode": "explicit_breakpoints"
   ```

   但会在契约读取前直接返回，无法应用显式断点。契约配置与运行时行为不一致。

   **修复：** 将 provider 硬编码早退改为基于 `get_contract(...).cache_mode` 判断，仅对 `explicit_breakpoints` 分派断点逻辑；未知模型再回退原有 caps 行为。

2. **Kimi 的 `prompt_cache_key_required` 没有实际注入**

   `_raw_stream` 虽读取契约，但最终仍受以下条件限制：

   ```python
   getattr(caps, "provider", "") == "openai"
   ```

   Kimi 契约明确要求 `prompt_cache_key`，但 Kimi provider 不会满足该条件，因此不会注入。现有测试只检查配置值，没有检查请求 payload。

   **修复：** 将是否注入 key 改为契约驱动；对 `requires_prompt_cache_key(...)` 为真的模型注入，并确保会话期恒定、模型切换时失效。

3. **schema 约束不足**

   `cache_contract` 未列入 record 的 required；契约中的关键字段如：

   - `cache_hit_discount`
   - `breakpoints_max`
   - `breakpoint_lookback`
   - `prompt_cache_key_required`
   - `thinking_param`

   均可缺失。当前 schema 不能保证“契约齐全”。

   **修复：** 为 `cache_contract` 和其必需字段增加 required，并视需要增加 `additionalProperties: false` 及模式间约束。

4. **限制性规范测试不是行为测试**

   以下测试基本只验证 JSON 字段，不能证明运行时满足规范：

   - reasoning/thinking echo
   - 模型切换后缓存实际失效
   - Claude 字节级前缀一致
   - Kimi key 会话恒定
   - Qwen 工具 schema 一致性

   **修复：** 增加 payload、消息序列、模型切换及 usage 处理的行为测试。
