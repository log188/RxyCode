# RxyCode 当前工作上下文

最后核对：2026-07-25。本文只记录可由当前工作区和本地验收结果复核的事实；早期 Agent 中断前的 JUnit、commit 和逐项 red-green 记录不可得，因此不补写历史基线。

## 产品定位

RxyCode 1.1.0 是 Python/FastAPI/LangGraph 后端与 React/Ink 原生终端前端组成的通用 Agent。它支持信息检索、文件和命令操作、软件开发、计划/构建/编排模式、会话恢复、审批和 Agent 提问。

项目路径：`D:/agent-demo/RxyCode/RxyCode1_1_0`。

## 本轮完成范围

- 工具调用统一经过 `ToolOrchestrator.execute_tool()`：模式权限、写路径、dry-run、审批、deadline、审计、事件和 evidence 共享同一入口。
- fast path 与 LangGraph proxy 使用相同的工具超时；原生异步工具在超时或用户取消时收到 cooperative cancellation，终态不会重复记录。
- Build/Compose 的并行派发、取消、调度和队列共享运行生命周期，避免重复副作用和跨请求取消。
- evidence 与 monitor 根据真实工具产物和失败 sentinel 决定终态，模型的乐观完成文本不能覆盖失败证据。
- research 路径对及时性问题强制搜索、抓取核验和来源输出；检索失败时明确拒绝猜测。
- CLI/API 会话以版本化 schema 保存完整 user/thinking/tool/assistant/system 角色、工具参数、结果和关联 ID，无固定消息截断。
- 前端使用增量 UTF-8 SSE parser、grapheme 编辑、完整历史、审批/提问弹窗和终端生命周期恢复；默认保留原生鼠标选择复制。
- API 默认绑定 `127.0.0.1` 并保护所有非只读端点；远程 opt-in 要求强 token 与 TLS。Provider onboarding 只允许 HTTPS。
- Provider 凭据不再内联 YAML：Windows 使用当前用户 DPAPI，其他平台使用 owner-only secret file，并支持旧配置迁移。
- 下载与 skill ZIP 安装具备 SSRF/DNS/redirect/content-size 和 zip-bomb 边界，发布前使用 staging 与原子替换。
- 测试按 unit/integration/contract/system/live/serial/pty 分层，CI 配置 Linux、Windows ConPTY 和独立 live lane。
- 标准 wheel/sdist 暴露 `rxycode` 与 `python -m RxyCode`；固定 tag 的 PowerShell/shell 安装器、`uvx` 即时运行和 tag-only GitHub Release workflow 已落地。
- 无模型 fresh-home 会进入 TUI 并允许 `/addmodel`；API Key 输入被遮蔽，首个模型初始化失败会回滚配置。
